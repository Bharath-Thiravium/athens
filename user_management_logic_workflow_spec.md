# Athens User Management Logic & Workflow Specification

## Overview
This document captures the business logic, user workflows, and screen content for Athens user management system. This specification is framework-agnostic and focuses purely on functional requirements.

---

## 1. USER HIERARCHY & TYPES

### Purpose
Multi-level user management system supporting project-based isolation with hierarchical user creation and management across different company types (Client, EPC, Contractor).

### User Types & Hierarchy

**Master Admin (Superuser)**
- `user_type` = 'master' OR `admin_type` = 'master'
- Top-level system administrator
- Can create projects and project admins
- Manages company details and logos
- Has access to all system functions

**Project Admin**
- `user_type` = 'projectadmin'
- `admin_type` = 'client', 'epc', or 'contractor'
- Created by Master Admin
- Can create and manage Admin Users within their project
- Manages their own company details

**Admin User**
- `user_type` = 'adminuser'
- `admin_type` = 'clientuser', 'epcuser', or 'contractoruser'
- Created by Project Admins
- End users who use the system features
- Must complete user profile details

---

## 2. ROLES & PERMISSIONS

### Master Admin Permissions
- Create projects and assign project admins
- View all projects across the system
- Reset passwords for any project admin
- Approve admin details for project admins
- Access consolidated dashboard data
- Manage menu configurations
- Delete projects (with dependency checks)

### Project Admin Permissions
- Create admin users within their project only
- View and manage users they created
- Edit/delete users they created
- Reset passwords for users they created
- Approve user details for users they created
- View project-specific data only
- Update their own admin details

### Admin User Permissions
- Submit and update their own user details
- View their own profile information
- Cannot create or manage other users
- Cannot access user management screens

### Permission Rules
**Create User:** Project Admin can create Admin Users in same project
**Edit User:** Creator OR Project Admin can edit when user in same project
**Delete User:** Creator OR Project Admin can delete when user in same project
**View Users:** Project Admin can view all users in their project
**Approve Details:** Creator OR Project Admin can approve user details
**Password Reset:** Creator OR Project Admin can reset passwords

---

## 3. PROJECT ISOLATION

### Isolation Rules
- All users belong to exactly one project
- Users can only see/manage data within their project
- Master Admin can see all projects
- Project Admins see only their assigned project
- Admin Users see only their project's data

### Company Inheritance
- Admin Users inherit company information from their creator
- EPC users always inherit from Master Admin's company details
- Client/Contractor users inherit from their Project Admin creator

## 4. USER CREATION WORKFLOW

### A) Master Admin Creates Project Admin

**Required Fields:**
- `username` - Unique username
- `user_type` = 'projectadmin'
- `admin_type` - 'client', 'epc', or 'contractor'
- `project` - Project assignment
- `company_name` - Company name
- `registered_address` - Company address

**Optional Fields:**
- `email` - Email address
- `name` - First name
- `surname` - Last name

**Default Values:**
- `is_autogenerated_password` = true
- `is_password_reset_required` = true
- `is_active` = true
- Auto-generated 16-character password

**Process:**
1. Master Admin provides project and admin details
2. System generates secure password
3. Project Admin account created
4. Credentials provided to Master Admin
5. Project Admin must reset password on first login

### B) Project Admin Creates Admin User

**Required Fields:**
- `username` - Unique username (auto-filled from email)
- `email` - Email address
- `name` - First name
- `surname` - Last name
- `department` - Quality, Safety, Inventory, Project/Execution
- `designation` - Role designation
- `grade` - A, B, or C (auto-suggested based on designation)
- `phone_number` - 10-digit phone number
- `user_type` = 'adminuser'

**Optional Fields:**
- Custom designation (can add new ones)

**Default Values:**
- `company_name` = creator's company_name
- `project` = creator's project
- `is_autogenerated_password` = true
- `is_password_reset_required` = true
- Auto-generated 16-character password

**Grade Assignment Rules:**
- Grade A: SiteIncharge
- Grade B: TeamLeader, Manager
- Grade C: All others

**Process:**
1. Project Admin fills user creation form
2. System auto-fills username from email
3. System suggests grade based on designation
4. System generates secure password
5. User account created with inherited project/company
6. Credentials downloaded as text file
7. New user must complete profile details

## 5. USER PROFILE DETAILS WORKFLOW

### Purpose
Admin Users must complete detailed profile information for approval before full system access.

### A) User Detail Submission

**Personal Details (Required):**
- `name` - First name
- `surname` - Last name
- `gender` - Male, Female, Other
- `father_or_spouse_name` - Parent/spouse name
- `date_of_birth` - Must be 18+ years old
- `nationality` - Country of citizenship

**Official Details (Required):**
- `employee_id` - Unique employee identifier
- `education_level` - Educational qualification
- `date_of_joining` - Employment start date
- `mobile` - 10-digit phone number
- `mark_of_identification` - Physical identification mark

**Identity & Financial (Required):**
- `uan` - 12-digit UAN number
- `pan` - PAN format: ABCDE1234F (5 letters + 4 digits + 1 letter)
- `aadhaar` - 12-digit Aadhaar number

**Document Attachments (Required):**
- `photo` - Profile photo (upload or camera capture)
- `pan_attachment` - PAN card image/PDF
- `aadhaar_attachment` - Aadhaar card image/PDF

**Read-Only Fields:**
- `department` - From user account
- `designation` - From user account
- `email` - From user account

**Validations:**
- Name/Surname: Letters and spaces only
- Phone/UAN/Aadhaar: Digits only, exact length
- PAN: Specific format validation
- Date of Birth: Must be 18+ years
- File uploads: Images or PDF, size limits

### B) Profile Photo Capture
**Methods:**
- File upload (drag/drop or browse)
- Camera capture using webcam
- Photo preview and replacement

**Requirements:**
- Required field for all users
- Image formats supported
- File size validation
- Camera permission handling

### C) Digital Signature Template
**Purpose:** Auto-generated signature template for document signing
**Process:**
- Template created automatically when profile submitted
- Uses user's name, surname, designation
- Stored for reuse across documents

## 6. APPROVAL WORKFLOW

### A) User Detail Approval Process

**Approval Authority:**
- Project Admin approves Admin User details
- Master Admin approves Project Admin details

**Approval States:**
- `is_approved` = false (default, pending approval)
- `is_approved` = true (approved, full access granted)

**Process:**
1. User submits complete profile details
2. System sends notification to approver
3. Approver reviews submitted details
4. Approver can approve or request changes
5. Upon approval, user gets full system access
6. System sends approval notification to user

### B) Approval Screen Content

**Pending Approvals List:**
- User name and basic info
- Submission date
- Company/department information
- Quick approve/view actions

**Detail Review Screen:**
- All submitted personal details
- Document attachments with preview
- Photo verification
- Approve/reject buttons

## 7. USER MANAGEMENT SCREENS

### A) User List Screen

**Columns Displayed:**
- Full Name (name + surname)
- Email
- Username
- Department
- Designation

**Actions Per Row:**
- View Details (eye icon) - always visible
- Edit User (edit icon) - visible when user can modify
- Delete User (delete icon) - visible when user can modify

**Permissions:**
- Admin Users: Cannot access (permission denied screen)
- Project Admins: See users they created in their project
- Master Admin: See all users across projects

### B) User Creation Modal

**Form Sections:**
1. Basic Information (email, username, name, surname)
2. Department and Role (department, designation, grade)
3. Contact Information (phone number)

**Features:**
- Email auto-fills username
- Designation auto-suggests grade
- Custom designation addition
- Form validation and error handling
- Credential download after creation

### C) User Edit Modal

**Editable Fields:**
- All fields from creation except username
- Password reset option
- Account status management

**Restrictions:**
- Can only edit users you created
- Cannot edit users from other projects
- Some fields locked after approval

### D) User Detail View

**Information Displayed:**
- Complete profile information
- Approval status
- Document attachments
- Contact details
- Employment information

## 8. PASSWORD MANAGEMENT

### A) Password Generation
**Auto-Generated Passwords:**
- 16 characters long
- Mix of letters, digits, and special characters
- Generated for all new accounts
- Marked as `is_autogenerated_password` = true
- Requires reset on first login

### B) Password Reset Rules

**Project Admin Password Reset:**
- Master Admin can reset any Project Admin password
- Project Admin can reset their own password
- New password provided by Master Admin

**Admin User Password Reset:**
- Project Admin can reset passwords for users they created
- Users in same project only
- New password provided by Project Admin

**Master Admin Password Reset:**
- Special superadmin key required
- One-time reset capability
- Controlled by system administrator

### A) Master Admin Company Details

**Fields:**
- `company_name` - Company name
- `registered_office_address` - Full address
- `pan` - Company PAN

**Usage:**
- Used by EPC users as inherited company data
- Displayed in headers and documents

### B) Project Admin Details

**Fields:**
- `name` - Admin name
- `phone_number` - Contact number
- `pan_number` - Personal PAN
- `gst_number` - Business GST
- `photo` - Profile photo
- `logo` - Company logo

**Approval Process:**
- Must be approved by Master Admin
- Pending approval blocks full access
- Notification sent on submission

## 11. EDGE CASES & ERROR HANDLING

### User Creation Errors
**Duplicate Username:**
- Error: "Username already exists"
- Solution: Suggest alternative username

**Invalid Email Format:**
- Error: "Please enter a valid email address"
- Validation: Email format checking

**Missing Required Fields:**
- Error: Field-specific validation messages
- Prevention: Form validation before submission

### Profile Submission Errors
**File Size Too Large:**
- Error: "File size must be less than 5MB"
- Handling: Client-side size checking

**Invalid Document Format:**
- Error: "Please upload image or PDF files only"
- Validation: File type checking

**Network/Upload Failure:**
- Error: "Failed to upload documents. Please try again."
- Retry: Allow resubmission

### Permission Errors
**Unauthorized Access:**
- Error: "Permission denied. Your user role does not have access."
- Redirect: Show permission denied screen

**Cross-Project Access:**
- Error: "You can only manage users in your project"
- Prevention: Filter data by project

### Approval Errors
**Already Approved:**
- Error: "User details are already approved"
- Prevention: Hide approve button for approved users

**Missing Approval Authority:**
- Error: "Only project admin can approve user details"
- Prevention: Role-based access control

## 12. NOTIFICATION SYSTEM

### Notification Types
**User Detail Submission:**
- Sent to: Project Admin (for Admin User) or Master Admin (for Project Admin)
- Message: "User has submitted their details for approval"
- Data: User ID, form type, submission details

**Approval Notification:**
- Sent to: User whose details were approved
- Message: "Your details have been approved"
- Data: Approval status, approver information

**User Creation:**
- Sent to: Newly created user (if email provided)
- Message: Account creation notification with credentials
- Data: Username, temporary password, login instructions

### Notification Delivery
- Real-time WebSocket notifications
- In-app notification center
- Email notifications (when configured)
- Persistent until acknowledged

## FINAL OUTPUT SUMMARY

### Core User Management Patterns

**Hierarchical Structure:**
- Master Admin → Project Admin → Admin User
- Project-based isolation at all levels
- Company inheritance from creators

**Profile Completion Flow:**
- Account creation → Profile submission → Approval → Full access
- Required for all Admin Users
- Document verification included

**Permission Model:**
- Creator-based permissions
- Project-scope restrictions
- Role-based feature access

**Advanced Permissions:**
